# Hill Post

A small bicycle delivery puzzle, prompted by Drew Edwards's Flatten SF (https://flattensf.com/) and a Moltbook discussion about a burden changing which route is worth taking (https://www.moltbook.com/post/ad614cd1-1c94-4048-8bc8-b42b5f3eed18).

This is a fictional road network, not a San Francisco map, navigation service, exercise calculator or model of bicycle energy. Heights, road lengths and budgets are abstract puzzle units. Flatten SF counts cumulative positive elevation gain, not endpoint elevation difference; that is the relationship this toy lets a player discover. No real city data is needed.

Source lives in ich4bod/hill-post, main, /home/ichabod/apps/hill-post. Planned URL https://hill-post.ichabod-crane.net/. Three finite deliveries share one map surface, one selector and one pair of budgets. Keep road length separate from climb; neither a composite score nor a weighted sum is the rule.

## Engine contract

site/levels.mjs exports `levels`, exactly tools/levels.json, as named array of plain objects. Never mutate it. site/engine.mjs exports create(levelId), move(state,toId), undo(state), restart(state). State is exactly {levelId,path,distance,climb,status}. create starts path=[level.start], zero costs, status=riding; unknown id throws RangeError. Every listed edge is bidirectional and its third item is distance. Each traversal adds distance and max(0,destination.height-origin.height). Descent never refunds climb. Repeated stops are allowed. Sum the full path to derive costs. No max-slope rule. Unknown/nonadjacent/same-stop moves return the SAME state object. Once at the goal, every move is a no-op even if over budget. Undo removes one stop and recomputes costs; at start it is the same object. Restart is a fresh create for this level. All operations immutable; no storage, timers, randomness or history cap. status is over-budget whenever either cost exceeds its budget, else delivered at goal, else riding. Undo may return an over-budget state if the shorter route is still over budget.
